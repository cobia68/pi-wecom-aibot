## ✅ 准备工作

| 准备项             | 说明                                                                                                 |
| :----------------- | :--------------------------------------------------------------------------------------------------- |
| 一台常开的电脑     | 关机、休眠或退出 pi 后机器人不再回复；同一个机器人同一时间只能在一台电脑、一个系统用户下连接         |
| pi                 | 1.3.0 或更高                                                                                         |
| Node.js            | 22.19.0 或更高，需要在 PATH 中                                                                       |
| Git                | 用于克隆插件仓库                                                                                     |
| 企业微信智能机器人 | 已开启 API 模式、长连接，并取得 BotID 和 Secret；没有时按 [第 1 步](#第-1-步创建企业微信机器人) 创建 |

## 📦 安装

插件还没有发布到 npm，从 Git 仓库或本地目录安装。两种方式都写入 pi 的全局设置（`~/.pi/agent/settings.json`），所有项目通用。

### 方式一：从 Git 仓库安装（推荐）

```bash
pi install git:github.com/cobia68/pi-wecom-bot
```

pi 会把仓库克隆到 `~/.pi/agent/git/github.com/cobia68/pi-wecom-bot`，并自动安装运行所需的依赖。

> [!TIP]
> 在末尾加 `@标签` 可以固定版本，例如 `pi install git:github.com/cobia68/pi-wecom-bot@v0.1.0`。固定后 `pi update` 不会改动它；换版本时用新标签再执行一次 `pi install`。请用标签而不是缩写的 commit 号，否则之后的 `pi update` 会失败。

### 方式二：从本地目录安装

适合先改代码再试用。pi 不会给本地目录安装依赖，需要自己装一次：

```bash
git clone https://github.com/cobia68/pi-wecom-bot.git
cd pi-wecom-bot
npm ci --omit=dev --legacy-peer-deps
pi install .
```

- `npm ci` 这一步不能省：缺少依赖时 `/wecom` 命令照样出现，但后台网关启动不了，机器人连不上。
- pi 直接从这个目录加载插件，装好后不要移动或删除它。
- Windows 和 Linux 请各用一份克隆，不要共用同一个 `node_modules`。

### 检查安装

重新打开 pi，或在已打开的 pi 中输入 `/reload`，再输入 `/wecom`：显示「未配置（运行 /wecom setup）」说明插件已加载。

## 🔌 连接机器人

### 第 1 步：创建企业微信机器人

1. 登录 [企业微信管理后台](https://work.weixin.qq.com/)，创建或打开一个「智能机器人」。
2. 在机器人配置页面开启「API 模式」，连接方式选「长连接」。
3. 记下 **BotID** 和 **Secret**。

> [!IMPORTANT]
> 连接方式请保持「长连接」，切换为「设置接收消息回调地址」会让插件断开。

### 第 2 步：在 pi 中配置

```text
/wecom setup
```

1. 按提示填入 BotID 和 Secret。
2. 「默认推送目标」选「自动识别：连上后给机器人发一条消息」。
3. 提示「已连接」后，在企业微信给机器人发一条消息：单聊直接发，群聊需 @机器人。
4. pi 显示识别到的聊天，确认后保存为默认推送目标。

这条消息只用于识别，不会被当成任务。想让通知默认发到某个群，就在那个群里 @机器人 发。

`/wecom setup` 只接入当前 pi，不会打开自动接入。希望以后每次打开 pi 都自动接入时，执行一次 `/wecom start`（之后新开的 pi 都会自动连接；`/wecom stop` 只影响当前窗口）。

### 第 3 步：发送测试

```text
/wecom test
```

企业微信收到一条「部署测试」消息，pi 提示「部署测试通知已获得企业微信服务端确认」，就接通了 🎉

## 🔐 设置白名单

> [!CAUTION]
> 默认情况下，任何能给机器人发消息的人，都能让 pi 在这台电脑上读写文件、执行命令。强烈建议只放行自己和信任的同事。

1. 收集 userid：你的 userid 在第 2 步识别时已显示（单聊时就是配置里的 `defaultChatId`）。同事的用 `/wecom whoami` 识别：执行后让同事给机器人发一条消息，询问是否设为默认推送目标时选否。
2. 打开 [配置文件](#-配置文件)，加上 `allowedUserIds`（记得给上一行末尾补英文逗号）：

   ```json
     "defaultChatType": 1,
     "allowedUserIds": ["你的 userid", "同事的 userid"]
   }
   ```

3. 在每个正在使用的 pi 窗口执行 `/wecom start`，新名单生效。

设置白名单后，`/wecom whoami` 只能识别名单内的人，所以先识别、再加名单。userid 以 `/wecom whoami` 显示的为准，可能和通讯录里的账号不同。

## 📝 配置文件

| 系统          | 位置                                           |
| :------------ | :--------------------------------------------- |
| Linux / macOS | `~/.pi/agent/wecom-bot.json`                   |
| Windows       | `C:\Users\你的用户名\.pi\agent\wecom-bot.json` |

实际位置以 `/wecom` 显示的为准。同一台电脑、同一系统用户下的 pi 窗口共用这份配置。`/wecom setup` 会写好 BotID、Secret 和默认推送目标，其余选项直接编辑：

```json
{
  "botId": "your-bot-id",
  "secret": "your-secret",
  "enabled": false,
  "screenMode": "text",
  "defaultChatId": "your-userid",
  "defaultChatType": 1,
  "welcome": "你好，我是 pi 智能助手。直接把问题或任务发给我即可。",
  "allowedUserIds": ["your-userid"]
}
```

| 字段               | 作用                                                                                                |
| :----------------- | :-------------------------------------------------------------------------------------------------- |
| `botId` / `secret` | 机器人的 BotID 和 Secret                                                                            |
| `enabled`          | 打开 pi 时是否自动接入企业微信，默认 `false`；`/wecom start` 会设为 `true`，`/wecom setup` 不会改它 |
| `allowedUserIds`   | 允许使用机器人的 userid 名单；不写或留空表示所有人都能用                                            |
| `defaultChatId`    | 默认推送目标：单聊填 userid，群聊填群 chatid                                                        |
| `defaultChatType`  | 默认推送目标类型：`1` 单聊，`2` 群聊                                                                |
| `welcome`          | 每天第一次打开单聊时的欢迎语                                                                        |
| `screenMode`       | 终端画面作为通知正文的形式：`text`（默认）发屏幕最后 20 行文字，`image` 发整屏图片；二选一          |
| `imageHosts`       | 可选，`screenMode` 为 `image` 时使用的图床列表，见 [终端画面通知](#-终端画面通知可选)               |
| `fontFiles`        | 可选高级字体覆盖；通常无需填写，默认按操作系统选择系统字体；仅图片模式使用                          |

- 改完后在每个正在使用的 pi 窗口执行 `/wecom start` 生效。只改欢迎语、默认推送目标、`screenMode` 或图片设置不会清掉排队任务和通知；更换 BotID、Secret 或 `allowedUserIds` 会撤销旧注册及其待处理工作。
- `enabled` 默认关闭：新开的 pi 不会自动接入，手动执行 `/wecom start` 会把它设为 `true` 并在当前窗口立即接入。
- Secret 和图床令牌以明文保存，请勿提交到代码仓库或发给他人。

## 💬 日常使用

### pi 状态栏

当前 pi 接入启动后（`/wecom start`，或按现有 `enabled` 设置自动启动），底部状态栏**只显示 `wecom-bot`**，不附加「在线」「重连中」等文字，也不加图标：

| 文字颜色（默认主题） | 含义                                                   |
| :------------------- | :----------------------------------------------------- |
| 绿色                 | 已完成网关注册和企业微信订阅，可以收发                 |
| 黄色                 | 正在连接，或断线后自动重连                             |
| 红色                 | 认证多次被拒绝、连接被接管等情况，已暂停重试，需要处理 |

**只有当前 pi 的接入已启动才显示**；仅有配置、未启动时不显示，执行 `/wecom stop` / `/wecom logout` 或退出后隐藏。每个 pi 独立显示自己的状态，查询 `/wecom` 不会启动接入。

文字保持不变，颜色随连接事件自动切换，无需手动刷新。采用 pi 的 `success` / `warning` / `error` 主题色，主题变化时也会更新；自定义主题以其配色为准。需要文字说明或排查红色状态时，用 `/wecom` 或 `/wecom log` 查看详情，处理后执行 `/wecom start`。

使用 pi 原生状态栏，不替换模型、用量等现有信息，也不覆盖其他扩展。不做动画或轮询，不显示凭据和聊天目标，不增加编辑区的空白行；RPC、JSON、print 模式不输出此标签。若使用自定义 footer，需要它支持显示 pi 的扩展状态。

### 发送任务

单聊直接发消息，群聊先 @机器人。机器人先回一条「执行中…」的状态消息，pi 处理完后改为「本轮已结束」，结果单独发一条会话通知。

- pi 正忙时新消息排队，按顺序处理。
- 任务超过约 10 分钟时，状态消息提前改为「任务仍在执行，请等待会话通知。」，完成后照常发结果。
- 同一个 pi 窗口里，所有企业微信聊天共用一份对话；需要分开时，开不同的 pi 窗口。

| 发送的内容 | pi 收到的是                                         |
| :--------- | :-------------------------------------------------- |
| 文字       | 直接作为任务                                        |
| 语音       | 自动转成的文字                                      |
| 图片       | 图片本身（需要所用模型支持看图）                    |
| 文件、视频 | 保存到项目的 `.pi-wecom-files/`，并告诉 pi 文件位置 |
| 引用消息   | 被引用的文字一起带上                                |

语音、图片、文件和视频只能在单聊中发送（企业微信的限制），单个文件不超过 50 MB。`.pi-wecom-files/` 不会自动清理，也不会被提交到 Git。

每个 pi 最多排队 50 条任务，同时准备 2 条消息的媒体（包括下载、解密、转换和保存）。尚未交给 pi 的图片 Base64 内容合计最多 128 MiB；超过预算的图片会附上失败说明，文字和已处理好的图片仍会交给 pi。交付、取消或停止时释放预算；这不限制 pi 自己的运行中输入或会话历史。媒体链接有效期较短，大量图片请分批发送。

### 同时开着多个 pi

- 只有一个 pi 在线时，消息直接交给它。
- 有多个时，机器人列出每个 pi 的项目文件夹、模型和会话编号，回复序号选择；触发选择的那条消息暂存 5 分钟，选好后自动交给它。
- 选好后，后续消息都交给同一个 pi；它退出或切换会话后会请你重新选择。群聊里每个人的选择互不影响。
- 引用某条会话通知回复，消息直接交给发出这条通知的 pi。

在企业微信里发 `/wecom sessions` 重新列出并选择，发 `/wecom use <会话编号>` 按通知里 `session:` 后的完整编号选择。

### 完成后通知

- **企业微信发起的任务**：结果自动发回原聊天。
- **电脑上布置的任务**：在任务里加一句「完成后发企业微信通知我」，pi 做完后推送到默认推送目标；要发到别的群，告诉 pi 那个群的 chatid。
- **断线恢复**：任务结果和已安排的完成通知在当前 pi 内保留快照，确定尚未发送时恢复连接后补发；若已尝试发送但确认丢失，则提示结果未知，不自动重复推送。明确被服务端拒绝的通知也不会自动重试。停止或退出当前 pi 会清除这些内存中的待发通知。

> [!NOTE]
> 企业微信要求对方先给机器人发过消息，机器人才能主动推送给他（或那个群）。通知是 Markdown：正文是要发送的文字，或按 `screenMode` 发送的终端画面（屏幕最后 20 行文字或整屏图片）。暂不支持单独发送图片或文件。

## 📸 终端画面通知（可选）

让企业微信里看到 pi 当前屏幕上显示的内容。正文二选一，由 `screenMode` 决定：

| `screenMode`   | 正文                                                               | 需要                   |
| :------------- | :----------------------------------------------------------------- | :--------------------- |
| `text`（默认） | 屏幕最后 20 行文字；超过通知上限时从头部截断，保留结尾             | 无，终端模式即可       |
| `image`        | 把整屏（不含编辑框和底部状态栏）画成 PNG，上传图床后以图片作为正文 | `imageHosts`、系统字体 |

两种模式不会同时发送：图片模式失败时改发屏幕文字，并在末尾注明原因。无论哪种模式，通知头部的目录、供应商/模型和 `session:` 三行来源信息始终是文字（也是引用回复时定位 pi 的依据），只替换下面的正文。

> [!NOTE]
> 图片模式没有使用企业微信原生的 `aibot_upload_media_` 图片消息：长连接只能发纯图片消息，无法在同一条里带来源文字；而多个 pi 共用一个网关时，媒体上传会话和两条消息的发送难以保持原子，重连后也容易重复或只剩一条。图片在各自的 pi 内上传、以 Markdown 图片链接发一条消息，才能保持现有的断线重发和确认语义。

执行 `/wecom start` 后：

```text
/wecom screen
/wecom screen your-group-chatid --chat-type 2
```

也可以直接告诉 pi：「把当前终端画面发到企业微信」或「完成后发通知，并附上最终画面」。只有明确要求时才会读取屏幕；`wecom_send` 的 `screen=true` 会用画面替换正文，不能同时给 `content`。

### 图片模式与图床

把 `screenMode` 设为 `image`，并在配置文件中加入 `imageHosts`（最多 5 项，按顺序尝试，前一个失败才用下一个）。`type` 只能是 `http`：

```json
{
  "botId": "your-bot-id",
  "secret": "your-secret",
  "screenMode": "image",
  "defaultChatId": "your-userid",
  "imageHosts": [
    {
      "type": "http",
      "url": "https://api.imgbb.com/1/upload",
      "fileField": "image",
      "fields": { "key": "your-api-key" },
      "urlPath": "data.url"
    }
  ]
}
```

| 字段                | 说明                                                                      |
| :------------------ | :------------------------------------------------------------------------ |
| `url`、`fileField`  | multipart 上传接口和文件字段名                                            |
| `fields`、`headers` | 可选，额外表单字段和请求头，值都是字符串；不要自己设置 Content-Type       |
| `urlPath`           | 可选，返回 JSON 中图片链接的路径，如 `data.url`；省略表示响应正文就是链接 |

- 🔒 图片会传给你配置的图床，请只使用可信服务并填最小权限凭据；插件不会替你清理已上传的图片。
- 上传接口和返回的图片链接都必须是 HTTPS，不跟随重定向，单次请求最多等 30 秒。
- 图片模式没配图床、找不到字体或上传全部失败时，改发屏幕文字，并在末尾注明原因。

### 字体（仅图片模式）

`text` 模式不需要字体。`image` 模式检测操作系统并使用本机字体，**不内置字体、不自动下载或安装字体**：

| 平台    | 中文字体策略                                                               |
| :------ | :------------------------------------------------------------------------- |
| Windows | 使用系统微软雅黑（Microsoft YaHei），同时加载可用的粗体                    |
| macOS   | 使用系统苹方，优先简体中文 `PingFang SC`；支持系统字体资源目录             |
| Linux   | 自动发现已安装的 CJK 中文字体，例如 Noto Sans CJK 或文泉驿；缺少时提示安装 |

英文和数字继续使用系统等宽字体，以保持终端代码、表格的列对齐。Windows/macOS 的默认中文字体不可用时，会提示检查或恢复对应的系统字体，而不是给出 Linux 安装命令。

Linux 缺少 CJK 字体时，中文截图会提示安装，但普通文字通知不受影响；只要有可用的英文字体，纯英文截图仍能生成。可按发行版手动安装：

```bash
# Debian / Ubuntu
sudo apt install fonts-noto-cjk fontconfig

# Arch Linux
sudo pacman -S noto-fonts-cjk fontconfig
```

安装后重试 `/wecom screen` 即可。无法生成图片时，屏幕文字照常发送，并附上原因和处理提示。

正常使用无需配置 `fontFiles`。已有的 `fontFiles` 仍作为高级覆盖项兼容（最多 8 个文件路径）；若要恢复平台默认策略，删除该项即可。

> [!CAUTION]
> 仅图片模式会上传图片：图片会带上屏幕上可见的工具输出和文件内容，拿到链接的人都可能看到。插件只尽力遮蔽它已知的 Secret 和图床令牌，其他敏感信息请发送前自己检查。text 模式只发文字，不会上传到图床。

两种模式都取 pi 终端模式下最新一屏，不含编辑框和底部状态栏；RPC、JSON、print 模式没有屏幕内容，只发原有文字并说明原因。

## 🧰 命令速查

| 命令            | 作用                                                                   |
| :-------------- | :--------------------------------------------------------------------- |
| `/wecom`        | 查看连接状态、默认推送目标和配置文件位置                               |
| `/wecom setup`  | 配置或更换 BotID、Secret，并重新连接                                   |
| `/wecom whoami` | 识别下一条消息所在的聊天，可设为默认推送目标                           |
| `/wecom test`   | 发送一条部署测试消息                                                   |
| `/wecom screen` | 把当前终端画面作为通知正文：屏幕文字或整屏图片（由 `screenMode` 决定） |
| `/wecom start`  | 当前 pi 开始接收企业微信消息，并重新读取配置                           |
| `/wecom stop`   | 当前 pi 停止接收企业微信消息                                           |
| `/wecom log`    | 查看最近 20 条运行记录                                                 |
| `/wecom logout` | 删除保存的配置并停止接收（需确认）                                     |
| `/wecom --help` | 查看全部命令；配置字段说明见 `/wecom setup --help`                     |

`/wecom stop` 只影响当前窗口：排队中的消息和待发通知被取消，已开始的任务在电脑上照常跑完，但结果不再发回企业微信。如果之前用 `/wecom start` 打开了自动接入，新开的 pi 仍会自动接入；不需要时把配置里的 `enabled` 改成 `false`。

`whoami` 等待或确认期间，如果机器人凭据被更换、配置被删除或当前注册被重启，旧识别结果不会写入配置，请重新识别。`logout` 若报告删除失败，当前 pi 已停止，但凭据可能仍在磁盘；请检查提示的文件权限后重试。

## 🔄 升级与卸载

### 升级

| 安装方式 | 命令                                                                     |
| :------- | :----------------------------------------------------------------------- |
| Git 仓库 | `pi update git:github.com/cobia68/pi-wecom-bot`                            |
| 本地目录 | 在插件目录执行 `git pull`，再执行 `npm ci --omit=dev --legacy-peer-deps` |

然后关闭所有使用这个机器人的 pi 窗口，再重新打开，新版本生效。当前本机网关协议为 v3（支持投递结果分类和欢迎语热更新），不能与旧网关混用；原配置文件无需迁移。

本次行为变化：`enabled` 的默认值改为 `false`（只影响新配置，已有文件里的 `true` 保持不变）；新增 `screenMode`，默认 `text`——以前配置了 `imageHosts` 会自动发图片，升级后要继续发整屏图片，请在配置里加上 `"screenMode": "image"`。

只执行 `pi update` 更新的是 pi 本身；`pi update --extensions` 更新所有已安装的插件。

### 卸载

1. 在 pi 中执行 `/wecom logout`，删除保存的 BotID 和 Secret。
2. 移除插件：
   - Git 仓库：`pi remove git:github.com/cobia68/pi-wecom-bot`，会一并删除克隆的仓库
   - 本地目录：在插件目录执行 `pi remove .`，只取消登记，不删除目录
3. 可选清理：各项目里的 `.pi-wecom-files/`，以及会话选择记录 `~/.pi/wecom-gateway/`。

## ❓ 常见问题

<details>
<summary><b>给机器人发消息没有反应</b></summary>

- 确认至少有一个 pi 正在运行并已接入：执行 `/wecom`，状态应为 `subscribed`。
- 群聊中需要先 @机器人。
- 设置了白名单时，名单外的人发的消息会被直接忽略。
- 执行 `/wecom log` 查看运行记录。出现 `gateway process exited` 或 `gateway launch failed` 时，多半是本地目录安装漏了 `npm ci`，或 PATH 中找不到 Node.js。

</details>

<details>
<summary><b>提示「机器人连接已被其他机器或旧客户端接管」</b></summary>

同一个机器人同一时间只能在一处连接。另一台电脑或另一个系统用户启用了同一个机器人时，这里会被挤下线。确认只在一处使用后，在任一 pi 中执行 `/wecom start` 恢复。

</details>

<details>
<summary><b>连接失败，提示核对 BotID/Secret</b></summary>

- 执行 `/wecom setup` 重新填写。
- 在企业微信管理后台确认机器人仍是「API 模式」+「长连接」。
- 连续被拒绝几次后插件停止重试；改好后执行 `/wecom start` 重新连接。

</details>

<details>
<summary><b>更换 BotID 或 Secret 后连不上</b></summary>

其他还开着的 pi 窗口仍在用旧配置。在这些窗口执行 `/wecom start` 读取新配置，或者关闭所有 pi 窗口后重新打开。

</details>

<details>
<summary><b>收不到主动推送</b></summary>

- 对方需要先在企业微信里给机器人发过消息。
- 企业微信限制每个聊天每分钟最多 30 条、每小时最多 1000 条消息。
- 没有默认推送目标时，用 `/wecom whoami` 设置，或在任务里写明发给谁。
- 失败原因可以在 `/wecom log` 中查看。

网络短暂中断时，已完成的结果会在恢复连接后补发；退出 pi 会取消还没发出的通知。

</details>

<details>
<summary><b>怎么查自己的 userid 或群的 chatid</b></summary>

执行 `/wecom whoami`，再让对方给机器人发一条消息（群聊需 @机器人）。pi 显示识别到的 chatid 和 userid，并询问是否设为默认推送目标，只想查看时选否。默认等 2 分钟，可用 `/wecom whoami --wait 300` 延长，最长 600 秒。

</details>

<details>
<summary><b>日志里经常出现 WebSocket closed，能否只在发送时连接</b></summary>

网关会自动重连：30 秒内恢复只记日志，超过 30 秒提醒一次，恢复后再提醒。日志里的 `1006` 只表示异常断开，不能据此判断是企业微信服务端还是中间网络造成的。

插件需要长连接实时接收任务和引用回复，断开期间收不到消息，所以保持连接。要暂停请用 `/wecom stop`。

</details>

<details>
<summary><b>机器人回复「当前等待任务较多，请稍后重试。」</b></summary>

每个 pi 最多排队 50 条消息，等前面的任务处理完再发。

</details>

## 🛠️ 开发

生产代码按运行归属组织：

- `src/extension/`：pi 侧入口、命令、会话桥接、状态栏、入站媒体和屏幕图片。
- `src/gateway/`：独立网关进程、会话路由和企业微信长连接。
- `src/shared/`：双方共用的协议、通知契约和格式规则，不依赖任何一端实现。

目录职责、依赖规则和迁移说明见 [文件组织架构](docs/architecture.md)。扩展入口由 `package.json` 的 `pi.extensions` 声明为 `src/extension/index.ts`；如果原先直接指定根目录 `index.ts` 加载，请更新路径。按包安装的用户无需修改设置。

开发时需要安装完整依赖，不要使用 `--omit=dev`；Windows 和 Linux 各用独立的克隆及 `node_modules`：

```bash
npm ci
npm run check
```

`check` 包含类型检查、递归发现的全部测试和真实 pi loader 的扩展加载检查。也可以单独运行：

```bash
npm test -- --test-name-pattern=notification
node --import tsx --test tests/shared/notification.test.ts
npm pack --dry-run --json
```

源码直接发布，不需要生成 `dist/`。新增生产文件放入 `src/`，测试放入 `tests/`，无需逐项修改发布白名单或测试命令。修改后在 pi 中执行 `/reload` 加载新入口。
