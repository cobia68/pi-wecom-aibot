## ✅ 准备工作

| 准备项             | 说明                                                                                                 |
| :----------------- | :--------------------------------------------------------------------------------------------------- |
| 一台常开的电脑     | 关机、休眠或退出 pi 后机器人不再回复；同一个机器人同一时间只能在一台电脑、一个系统用户下连接         |
| pi                 | 1.3.0 或更高                                                                                         |
| Node.js            | 22.19.0 或更高，需要在 PATH 中                                                                       |
| Git                | 用于克隆插件仓库                                                                                     |
| 企业微信智能机器人 | 已开启 API 模式、长连接，并取得 BotID 和 Secret；没有时按 [第 1 步](#第-1-步创建企业微信智能机器人) 创建 |

## 📦 安装

插件还没有发布到 npm，从 Git 仓库或本地目录安装。两种方式都写入 pi 的全局设置（`~/.pi/agent/settings.json`），所有项目通用

### 方式一：从 Git 仓库安装（推荐）

```bash
pi install git:github.com/cobia68/pi-wecom-aibot
```

pi 会把仓库克隆到 `~/.pi/agent/git/github.com/cobia68/pi-wecom-aibot`，并自动安装运行所需的依赖

> [!TIP]
> 在末尾加 `@标签` 可以固定版本，例如 `pi install git:github.com/cobia68/pi-wecom-aibot@v0.1.0`。固定后 `pi update` 和 `pi update <source>` 都不会改动它；换版本时用新标签再执行一次 `pi install`。请用标签而不是缩写的 commit 号，否则之后的 `pi update` 会失败

### 方式二：从本地目录安装

适合先改代码再试用。pi 不会给本地目录安装依赖，需要自己装一次：

```bash
git clone https://github.com/cobia68/pi-wecom-aibot.git
cd pi-wecom-aibot
npm ci --omit=dev --legacy-peer-deps
pi install .
```

- `npm ci` 这一步不能省：缺少依赖时 `/wecom-aibot` 命令照样出现，但后台网关启动不了，机器人连不上
- pi 直接从这个目录加载插件，装好后不要移动或删除它
- Windows 和 Linux 请各用一份克隆，不要共用同一个 `node_modules`

### 检查安装

重新打开 pi，或在已打开的 pi 中输入 `/reload`，再输入 `/wecom-aibot status`：第一行显示「💤 企业微信智能机器人：未接入」说明插件已加载，还没有配置时会提示先运行 `/wecom-aibot config --scope global edit`

## 🔌 连接机器人

### 第 1 步：创建企业微信智能机器人

1. 登录 [企业微信管理后台](https://work.weixin.qq.com/)，创建或打开一个「智能机器人」
2. 在机器人配置页面开启「API 模式」，连接方式选「长连接」
3. 记下 **BotID** 和 **Secret**

> [!IMPORTANT]
> 连接方式请保持「长连接」，切换为「设置接收消息回调地址」会让插件断开

### 第 2 步：在 pi 中配置

```text
/wecom-aibot config --scope global edit
```

1. 按提示填入 BotID 和 Secret
2. 「默认推送目标」选「发验证码识别」：pi 用刚填的凭据临时连接企业微信，并显示一个 6 位验证码。凭据填错时这一步就会报错
3. 在要接收通知的聊天里把验证码发给机器人（群聊需 @机器人）。pi 显示识别到的聊天，凭据和目标一起保存，临时连接随即关闭

知道 userid／chatid 时也可以选「手动填写」。只有这条验证码会被当成识别，其他消息照常处理；想让通知默认发到某个群，就在那个群里 @机器人 发验证码。以后换目标用 `/wecom-aibot config --scope global whoami`

`config` **只修改配置，不自动正式接入，也不发送控制卡**。识别时的临时连接不接收任务、不出现在在线会话列表，完成、取消或超时后关闭。每个 session 都必须手动执行 `/wecom-aibot connect`，新建、恢复、分叉和 `/reload` 后也不例外；退出或切换会话时自动 disconnect。`connect` / `disconnect` 不修改配置，也不影响其他已接入的 pi

没有交互界面（如 print 模式）时不能使用 `edit`，凭据请直接写入 [配置文件](#-配置文件)

### 第 3 步：正式接入并测试

```text
/wecom-aibot connect
/wecom-aibot test
```

`connect` 要求 BotID、Secret 和默认推送目标齐全。网关注册与企业微信订阅成功后，这个 session 在默认聊天里首次发送一张控制卡：标题是工作目录，「会话」下拉框列出所有在线会话，带「刷新卡片」「发提示词」「切换模型」「中止任务」四个按钮。点卡片的引用区打开这个会话的文档页，看最近的回复（要先配置会话文档），详见[每个 session 的控制卡](#每个-session-的控制卡)。直接发消息即可布置任务，见[发送任务](#发送任务)

**每次执行 `/wecom-aibot connect` 都在默认聊天发一张新控制卡**，未就绪时等注册与订阅成功后再发；已经接入时再执行一次也会发。卡上的「会话」下拉框列出发卡那一刻在线的所有会话：依次 connect 三个会话，第一张卡列 1 个，第二张列 2 个，第三张列 3 个，最新的一张总是全的。旧卡不会自己更新，点一下按钮就换成当前列表。网络断线重连、共享网关替换不发，继续用已发的卡。旧卡不撤回，点击时就地换成当前版式。控制卡发送失败不代表连接失败，可用 `test` 排查

企业微信收到一张控制卡，「窗口记录」写着「🧪 部署测试」，pi 提示「部署测试通知已获得企业微信服务端确认」，就接通了 🎉 再点卡片上的「刷新卡片」，卡片几秒内记下结果，说明按钮回调也通了

## 🔐 设置白名单

> [!CAUTION]
> 默认情况下，任何能给机器人发消息的人，都能让 pi 在这台电脑上读写文件、执行命令。强烈建议只放行自己和信任的同事

1. 收集 userid：你的 userid 在第 2 步识别时已显示（单聊时就是配置里的 `defaultChatId`）。同事的用 `/wecom-aibot config whoami` 识别：把 pi 显示的验证码发给同事，让他发给机器人；不写 `--scope` 时只显示，不保存
2. 打开全局 [配置文件](#-配置文件) `config.json`，加上 `allowedUserIds`（记得给上一行末尾补英文逗号）。这一项不由 `config` 命令管理，只能写在全局配置里：

   ```json
     "defaultChatType": 1,
     "allowedUserIds": ["你的 userid", "同事的 userid"]
   }
   ```

3. 在每个正在使用的 pi 窗口执行 `/wecom-aibot connect`，新名单生效。网关按各窗口接入时的名单放行：收紧名单后，没有重新接入的窗口仍按旧名单放行，撤销权限时请逐个重新接入

识别不受白名单限制：验证码只显示在你的屏幕上，设了白名单以后也能识别新同事。识别不等于授权，发任务仍要在白名单里。userid 以 `/wecom-aibot config whoami` 显示的为准，可能和通讯录里的账号不同

## 📝 配置文件

配置分两层，都用 `/wecom-aibot config` 查看和修改：

- **全局配置**：同一台电脑、同一系统用户下的所有 pi 窗口共用
- **session 覆盖**：只属于一个 pi 会话，只保存这个会话里显式设置过的字段

```text
/wecom-aibot config                                        # 列出全部写法供选择
/wecom-aibot config show                                   # 当前 session 合并后的配置，标明每项来源
/wecom-aibot config --scope global edit                    # 交互编辑全局配置
/wecom-aibot config --scope session set controlPrompts=继续,运行测试
/wecom-aibot config --scope session unset controlPrompts   # 删除覆盖，重新继承全局值
/wecom-aibot config --scope global whoami                  # 发验证码识别聊天，设为全局默认推送目标
```

会话文档地址（`docMcpUrl`）也在 `config --scope global edit` 里填写，见[每个 session 的控制卡](#每个-session-的控制卡)

| 系统          | 位置                                         |
| :------------ | :------------------------------------------- |
| Linux / macOS | `~/.pi/agent/wecom-aibot/`                   |
| Windows       | `C:\Users\你的用户名\.pi\agent\wecom-aibot\` |

实际位置以 `/wecom-aibot status` 显示的为准。这个文件夹属于插件自己：`config.json` 是全局配置，`sessions/` 放各 session 的覆盖（按 session ID 命名），`gateway/` 放共享网关的 socket；`PI_CODING_AGENT_DIR` 改变时整个文件夹随之移动

优先级：内置默认值 < 全局配置 < session 覆盖。BotID 与 Secret、默认推送目标与类型各自成组，整组取自同一层，session 的 BotID 不会配上全局的 Secret

- 作用域是命令的目标，写在动作前：`config --scope <global|session> <动作>`，和企微侧 `--session-id <id> <动作>` 一样。`edit`、`set`、`unset` 必须写；`show`、`whoami` 不写时只读：`show` 显示合并结果，`whoami` 只识别不保存。写在动作后会报错并给出正确写法
- 只输入 `config` 时不执行任何动作，而是列出全部写法供选择，`config --scope global` 只列全局的：`show`、`edit`、`whoami` 选中即执行；`set`、`unset` 把命令填进输入框，补上 `字段=值` 后回车。没有交互界面时只列出这些写法
- `set` 写成 `字段=值`，字段名即 JSON 键名，大小写不敏感；一条命令可写多个字段，有任何错误时一项都不保存
- BotID、Secret 和会话文档地址只能用 `edit` 输入：`set` 的命令文本会留在 pi 的输入历史里。`edit` 输入时它们显示在屏幕上，之后查看时只显示「已配置」
- 没有交互界面时不能使用 `edit`，凭据请直接编辑 `config.json`

```json
{
  "botId": "your-bot-id",
  "secret": "your-secret",
  "defaultChatId": "your-userid",
  "defaultChatType": 1,
  "notificationScope": "wecom-tasks",
  "allowedUserIds": ["your-userid"]
}
```

| 字段                | 作用                                                                                      |
| :------------------ | :---------------------------------------------------------------------------------------- |
| `botId` / `secret`  | 机器人的 BotID 和 Secret                                                                  |
| `defaultChatId`     | 默认推送目标：单聊填 userid，群聊填群 chatid                                              |
| `defaultChatType`   | 默认推送目标类型：`1` 单聊（只给 `defaultChatId` 时即为单聊），`2` 群聊                   |
| `notificationScope` | 自动结束通知范围：`wecom-tasks`（默认）只回传企微下发的任务；`all-runs` 时**本地终端里自己敲的提示词跑完也发通知**到默认目标（没有默认目标则不发），企微任务不重复发送 |
| `controlPrompts`    | 控制卡「发提示词」的候选，最多 10 条，按顺序显示；点「发提示词」后在下拉框里选一条，点「确认发送」把它原样作为本 session 的任务。下拉框只显示每条的前 10 个字，发出去的是整条。`set` 用英文逗号分隔（`controlPrompts=继续,运行测试`，中文逗号算在提示词里）；含空格或英文逗号的用 `edit` 一行一条填写，清空编辑器即为没有提示词。全局和 session 都能设。不设置时没有提示词，控制卡不显示下拉框和「发提示词」 |
| `docMcpUrl`         | 会话文档地址：智能机器人「文档」授权后的 streamableHTTP URL。只能写在全局配置里，只能用 `config --scope global edit` 填写；地址含 apikey，查看时只显示是否已配置。不配置时，控制卡「刷新卡片」只更新卡片上的三行 |
| `allowedUserIds`    | 允许使用机器人的 userid 名单；不写或留空表示所有人都能用。只能写在全局配置中，不由 `config` 管理；`config whoami` 识别出名单外的人时，会问要不要加入 |

- 保存配置从不断开或重连。`notificationScope`、`controlPrompts`、`docMcpUrl` 用到时现读，所有 pi 窗口下次使用时生效，无需 `connect`；已生成、等待发送的通知保持原快照
- BotID、Secret、默认推送目标和 `allowedUserIds` 只在 `connect` 时采用。改变后，`status`、`config show` 和状态栏显示「待重新接入」，当前接入仍使用旧配置；运行 `/wecom-aibot connect` 确认后切换。切换会撤销旧注册，清除排队任务和待发通知，已开始的任务继续运行但结果不再回传。没有交互界面时，只有没有待处理工作才直接切换
- `config --scope <global|session> whoami` 确认后把目标保存到那一层，不断开当前接入。识别用那一层生效的机器人；pi 正连着另一个机器人时，先 `disconnect` 再识别
- 分叉出的 session（`/fork`、`/clone`、`--fork`）首次启动时复制一次父 session 的覆盖项并提示，之后两边各自独立。连接状态不复制，也不保存到配置文件
- Secret 以明文保存，请勿提交到代码仓库或发给他人。删除 pi 会话不会删除它的覆盖文件，不需要时手动清理 `sessions/`

## 💬 日常使用

### pi 状态栏

当前 session 手动接入并**首次连接成功后**，底部状态栏只显示 `wecom-aibot`，不附加「在线」「重连中」等文字，也不加图标：

| 文字颜色（默认主题） | 含义                                                   |
| :------------------- | :----------------------------------------------------- |
| 绿色                 | 已完成网关注册和企业微信订阅，可以收发                 |
| 黄色                 | 已连接过，但当前断线，正在自动重连                     |
| 红色                 | 认证多次被拒绝、连接被接管等需要处理的情况；`/wecom-aibot disconnect` 后的约 1.5 秒也是红色 |

已接入后，配置文件里的接入配置（凭据、默认目标或白名单）改变时，标签后追加警示色的「（待重新接入）」，运行 `/wecom-aibot connect` 后消失

**首次连接未就绪前不显示标签**，也不往 pi 正文追加「正在注册」「已连接」的静态通知；重复执行 `/wecom-aibot connect` 不重复提示。注册与订阅均可用后才显示绿色标签，并在默认聊天发一张该 session 的新控制卡。首次等待超过 30 秒会提醒一次，可用 `/wecom-aibot status`、`/wecom-aibot log` 排查，或 `/wecom-aibot disconnect` 取消；明确失败会提示原因

成功连接后才用颜色跟踪断线和恢复。执行 `/wecom-aibot disconnect` 后标签先变红约 1.5 秒再隐藏，让「为什么没有反应」有个交代；`/wecom-aibot reset`、退出、切换会话或 `/reload` 后直接隐藏，新 session 必须重新手动连接。每个 pi 独立显示自己的状态，查询 `/wecom-aibot status` 不会启动接入

文字保持不变，颜色随连接事件自动切换，无需手动刷新。采用 pi 的 `success` / `warning` / `error` 主题色，主题变化时也会更新；自定义主题以其配色为准。需要文字说明或排查红色状态时，用 `/wecom-aibot status` 或 `/wecom-aibot log` 查看详情，处理后执行 `/wecom-aibot connect`

使用 pi 原生状态栏，不替换模型、用量等现有信息，也不覆盖其他扩展。不做动画或轮询，不显示凭据和聊天目标，不增加编辑区的空白行；RPC、JSON、print 模式不输出此标签。若使用自定义 footer，需要它支持显示 pi 的扩展状态

### 发送任务

网关**不记「当前目标」**。每条普通消息（文字、语音、图片等）发给哪个会话，只看这条消息本身，按顺序：

1. **命令写明 session ID**：`/wecom-aibot --session-id <ID> send --prompt <正文>`
2. **引用某个会话的消息**：引用一条开头带 `🆔 session: <ID>` 的消息，再输入正文，就发给那个会话。可引用的有：机器人的文字回复，如「没有执行」的说明和卡片被拒收时改发的 Markdown；任务结果是卡片，引用不了。引用图片或文件定位不了会话，机器人照样问发给谁。**卡片引用不了**：企业微信引用卡片时只给机器人一行「[该消息类型暂不能展示]」
3. **其他情况**：机器人回一张卡问「这条消息发给哪个会话？」：正文每个会话一行「忙闲 | 文件夹 · session ID 末 4 位 · 模型」（最多 5 行），「会话」下拉框写「文件夹 · ID 末 4 位 · 忙闲」（最多 10 个）。同一个文件夹开了几个会话，靠 ID 末 4 位区分，和控制卡 `🆔` 那一行的结尾对得上；文件夹名太长先截文件夹，ID 和忙闲留着。选好点「确认发送」就发给它，点「取消发送」就不发。下拉框默认选第一个，不动直接确认就发给它；只有一个会话在线也要点一下「确认发送」

问一次只对这一条有效，下一条没有引用的消息再问；不会因为上一条选了谁，下一条就自动发过去。点了「确认发送」以后，问的卡变成「已发送」：标题是目录（`📁 目录`），下面是模型（`🤖 模型 · 服务商`）、你的消息和 `🆔 session-id`，和控制卡写法一样，点错了一眼能看出来，可以在控制卡上「中止任务」；session ID 可以复制来用 `--session-id`。取消、过期或会话刚好离线时变成「未发送」，写明原因。运行期间不发「执行中…」之类的状态消息；pi 跑完后，结果以一张结果卡发到这个聊天，跑多久都一样，接着说就在结果卡上点「发提示词」。消息没能执行（排队太多、处理失败、清空排队、转发停止）时，24 小时内回复这条消息说明原因

问的卡 4 分钟内有效（附件链接 5 分钟后失效）。过期、点了「取消发送」，或者同一个人在同一个聊天又发了一条没有引用的消息，前一条就不再发出，机器人回复它说明原因。群聊里只有发消息的人能选，别人点了只在自己那份卡上看到「只有发送者能选择」

```text
/wecom-aibot sessions
/wecom-aibot --session-id <完整 session ID>
/wecom-aibot --session-id <完整 session ID> send --prompt <正文>
/wecom-aibot --session-id <完整 session ID> card
/wecom-aibot --session-id <完整 session ID> cancel
/wecom-aibot --help
/wecom-aibot send --help
```

- `--session-id` 是整条命令的目标，必须写在动作前，和 pi 命令行、卡片上的写法一样；以前的拼法 `--sessionid` 照样能用。写在动作后（`cancel --session-id <id>` 等）只报错并给出新写法，不执行
- `sessions` 不需要目标，发送一张在线会话卡，写法见[欢迎与在线会话卡](#欢迎与在线会话卡)。不选目标
- 列表当场询问 pi，最多等 2 秒，没回答的显示「状态未知」；状态和时间是当次查询的快照，不会自行刷新。只显示发送者白名单允许访问的正式接入会话
- 只写 `--session-id <id>` 时，当场询问该会话的忙闲，回复「目录 · 供应商 · 模型 · 忙闲」一行，再列出三条填好 ID 的 `send`、`card`、`cancel` 命令，方便直接复制；最多等 2 秒，没有回答时显示「状态未知」。这只是查询；ID 不在线时回「找不到这个 session ID」并附上当前会话列表
- `send` 的正文从 `--prompt` 之后开始，空格、换行和 `--` 开头的文字都原样保留；`--prompt` 必须放在最后，其后不再解析任何选项，出现 `--session-id <uuid>`、`--help` 等也只是正文
- `card` 在当前聊天显式补发目标 session 的控制卡；会产生一张新卡，旧卡仍可操作同一个在线 session。不启动任务
- `cancel` 请求中止该会话正在运行的一轮；中止是异步生效的
- `--help` 是总帮助，`send --help` 等是单个动作的帮助，都不需要目标；带目标的 `--session-id <id> send --help` 同样只显示帮助，不查询或执行，目标离线也不影响查看帮助
- 参数只用空格分隔，不支持 `=`；未知选项会报错并列出可用选项
- 命令中显式写出的 `--session-id` 决定目标，引用不能改变它；不带目标的 `send`、`card`、`cancel` 仍报缺少目标，不从引用补目标
- **引用卡片定位不了会话**：企业微信引用卡片时只给机器人一行「[该消息类型暂不能展示]」，不带卡片上的任何内容。机器人照样问这条消息发给谁，卡上写明「引用的是卡片」，选好会话点「确认发送」就行

| 发送的内容 | pi 收到的是                                         |
| :--------- | :-------------------------------------------------- |
| 文字       | 普通消息原文，或命令里 `--prompt` 之后的正文         |
| 语音       | 自动转成的文字（在问的卡上选会话）                  |
| 图片       | 图片本身（需要模型支持看图；在问的卡上选会话）      |
| 文件、视频 | 保存到项目的 `.pi-wecom-aibot-files/`，在 `[attachments]` 段里告诉 pi 文件位置 |
| 引用消息   | 被引用的文字放在 `[quote]` 段里一起带上；引用的图片、文件不会带给 pi，正文里也不会留下「[图片]」 |

交给 pi 的每条消息，第一行写来源：`[wecom|from:<userid>|chat:单聊]`，群聊写 `chat:群聊`，不写聊天的 chatid。这一轮的系统提示里还会加一段说明：结果会以控制卡发回这个聊天、在手机上看、不要写密钥、怎样给出下一步

语音、图片、文件和视频只能在单聊中发送（企业微信的限制），单个文件不超过 50 MB。`.pi-wecom-aibot-files/` 不会自动清理，也不会被提交到 Git

每个 pi 最多排队 50 条任务，同时准备 2 条消息的媒体（包括下载、解密、转换和保存）。尚未交给 pi 的图片 Base64 内容合计最多 128 MiB；超过预算的图片会附上失败说明，文字和已处理好的图片仍会交给 pi。交付、取消或停止时释放预算；这不限制 pi 自己的运行中输入或会话历史。媒体链接有效期较短，大量图片请分批发送

### 每个 session 的控制卡

pi 发到企业微信的卡片都是控制卡：connect、补发、任务完成、`wecom_send` 通知、部署测试，区别只在初始状态和「窗口记录」。每个 session 在每个聊天维护自己的控制卡，不依赖其他 session 什么时候 connect 或发送结果。卡片的内容、状态和送达记录由所属 pi 管理；网关只负责渲染、补全会话列表、投递和把点击转给正确的 pi，仍然只有一条共享企业微信长连接

```text
[pi] 执行中                        ← pi 图标加状态：空闲灰、执行中绿；等待确认中止、文档不可用、会话已离线为红
📁 pi-wecom-aibot                   ← 工作目录
🤖 模型 · 供应商                    ← 模型在前；过长时换行，超过 40 字截断，截掉的是供应商的末尾
┃ $ npm run check                   ← 终端最后三行有字的输出（整行，不截断，不写时间）；点开是本 session 的文档页
┃ ✔ 483 passed
┃ 检查全部通过，改动未提交
🆔 session-id: <完整 session ID>     ← 和 pi 命令行的 --session-id 同一写法
窗口记录  13:57 已刷新（2.1 秒）     ← 最近一次点按钮的结果（刷新、发送提示词、中止等），不是链接；新卡写「已接入」，补发的写「已补发控制卡」
会话  [ pi-wecom-aibot ▾ ]          ← 所有在线会话，默认是卡上这个；选了别的再点任一按钮，卡就换成那个会话
[ 刷新卡片 ] [ 发提示词 ]                          ← 总是四个按钮，两行两列：一行三个会被截成「刷新…」
[ 切换模型 ] [ 中止任务 ]                          ← 常用的在第一行；会停掉工作的「中止任务」在最后，离「刷新卡片」最远
```

- **切换会话**：在「会话」下拉框选另一个会话，再点任一按钮，这张卡就换成那个会话（同时刷新画面），按钮这一次不执行，「窗口记录」写「已切换到本会话」。看清了再点，按钮才作用于它，所以「中止任务」不会误中别的会话。下拉框最多 10 个：超过时卡上的会话一定在，其余取最近用过的 9 个，卡上写「另有 N 个会话」；每项写「文件夹 · session ID 末 4 位」（控制卡不问各会话忙闲，所以不写状态）。列表在点击时更新，新会话 connect 后，旧卡点一下才列出它。群聊里只换点击人那一份。没有权限的会话不列出，选了也不响应
- **看回复**：点卡片的引用区，打开这个会话的文档页：最近 3 轮的提问和回复（新的在上）、最近的 `wecom_send` 通知正文，都按正文显示。回复保留 Markdown 格式，很长的会截断；终端画面不放进页面，卡上的三行就是它的结尾。不往聊天里发消息，长回复也不会刷屏
- **刷新卡片**：读取 pi 编辑框以上最新一屏的文字（不读 scrollback；编辑框、pi 状态栏和 footer 都不读），去掉颜色，遮盖 Secret 和文档地址，更新卡片上的三行（RPC、JSON、print 模式没有终端界面，这时「窗口记录」写明读取失败）；配置了会话文档时，再重写本 session 的文档页（最近的回复和通知）。点击后约 3 秒内把实际结果写在卡片上；文档来不及写完时卡片写「页面仍在写入」，写入继续，下次刷新可见。不启动模型调用或新任务
- **发提示词**：分两步。点「发提示词」，下拉框换成提示词，按钮换成「确认发送」「取消发送」；选好再点「确认发送」，选中的那一条作为本 session 的一次任务。一张卡只能有一个下拉框，所以提示词和会话轮流用它。候选先是这张卡的结果给出的下一步（见下一条），再是配置字段 `controlPrompts`；都没有时按钮照样在，点了提示去设置。改了以后下一次点「发提示词」生效；已被删掉或改过的那一条不会发出，「窗口记录」提示重选。pi 空闲就开始，忙时和企微消息一起排队，卡片写明前面有几条。卡片点击不能开流式回复，所以没有「执行中…」状态消息，结果以一张完成状态的控制卡发到这张卡所在的聊天。群聊里只有点击人那份卡换成提示词
- **切换模型**：分两步。点「切换模型」，下拉框换成这个会话可用的模型，正在用的排第一并选中，按钮换成「确认切换」「取消切换」；选好再点「确认切换」。模型取 pi 的 scoped models（`--models` 或 `enabledModels`），没配就取已有密钥的全部模型。企业微信的下拉框最多 10 项，超过 10 个模型时分页：按钮第二行是「上一页」「下一页」（到头从另一端接上），下拉框标题写「模型 2/3」这样的页码，从第一页开始，正在用的排第一。只翻页不选、直接点「确认切换」，切到这一页的第一个（企业微信这时显示的就是它）。同一个模型挂在几个中转上时排在一起，名字后面写供应商，去掉它们共有的开头（`welfare-agentrouter-fbw` 和 `welfare-anyrouter` 写成 `agentrouter-fbw`、`anyrouter`）；太长时先截名字（留 12 个字）再截供应商，每项最多 32 个字。正在跑的一轮不受影响，下一轮起用新模型；卡片第三行随即显示新模型。只改这个会话，不改 pi 的默认模型
- **下一步**：以卡片发出的结果（企微发来的任务、「发提示词」的任务、`all-runs` 的本地运行、`wecom_send` 的通知）可以在回复末尾写一段隐藏注释，如 `<!-- wecom_next ["运行测试", "提交改动"] -->`，列出下一步，最多 10 条，排在这张卡「提示词」下拉框的最前面。发往企业微信的内容、卡片引用区和文档页都去掉这段注释，pi 终端里照样显示。下一步记在 pi 的内存里，pi 重启后旧卡只剩 `controlPrompts`
- **中止任务**：分两步。空闲且没有排队时只记下「当前没有运行中的任务」；执行中时按钮换成「确认中止」「取消中止」。有排队的任务时是四个：「确认中止」只停这一轮，「全部中止」连排队的一起清掉，「清空排队」只清排队，「取消中止」不动。60 秒内由同一个人点才生效；「确认中止」与 `cancel` 相同。被清掉的企微消息会收到回复「这条消息没有执行：已在控制卡上清空排队」。有排队时来源行写「执行中 · 排队 2」这样的排队数，是点击时的快照。超时再点只记下「确认已过期」。群聊里只有点「中止任务」的人看到确认按钮（其他人的卡片不变），别人点到「确认中止」也不生效。群聊的这一行为未经实测
- **何时发送**：每次 `/wecom-aibot connect` 向默认聊天发一张新的；首次接受另一个聊天的任务时，也为那个聊天发一张（那个聊天已有本会话的送达记录时不再发）。每张卡的下拉框列出发卡时在线的所有会话。任务不会为了等控制卡的发送确认而阻塞
- **何时复用**：网络重连、网关替换、模型切换都不发新卡，继续用最近发出的那张；任务结果和通知各发一张新的。状态和画面是刷新时的快照，不是一直有效的在线承诺
- **不能主动刷新**：企业微信只允许在用户点击后的 5 秒内更新卡片。任务开始、结束、模型切换或 session 离线时都不会主动改卡；结果和通知各发一张新卡，不覆盖旧卡
- **断开和恢复**：其他 pi 仍在线时，点击已离线 session 的旧卡，卡片顶部变成红色「会话已离线」。同一 session 恢复接入后，旧卡还能找到它；即使网关不记得卡片内容，也可向所属 pi 获取最新内容来重绘。旧版本发出的控制卡，点任何按钮都只刷新，就地换成新版式，不执行旧按钮的动作
- **显式补发**：企微侧 `/wecom-aibot --session-id <id> card`。会生成新的物理消息，旧卡不撤回且仍可用。在线会话卡上点「打开会话」效果相同，列表还留着
- **发送失败**：只有确定没发送的控制卡在连接恢复后重试。已被拒绝或结果未知的不会自动重复发送，需要时显式补发；写入送达记录失败时不会开始发送

送达记录保存在 pi session 的扩展元数据中，**不进入模型上下文，也不恢复连接同意**：恢复会话后仍必须手动 connect。记录包含 BotID、聊天标识、卡片 ID 和送达状态，不包含 Secret 或正文；导出或分享 session 时这些元数据也会包含在内。`/tree` 切换分支不会撤销已经发生的投递，`/fork`、`/clone` 产生的新 session 则创建自己的卡片。不持久化的 pi 会话无法在退出后恢复这些记录

控制卡和记录**不会延长网关生命周期**：最后一个 pi 断开后网关仍约 1.5 秒退出。没有任何 pi 接入时，聊天历史里的旧卡不会自动消失，但点击也不会启动网关

#### 会话文档

卡片只能显示三行，最近的回复和通知写在企业微信智能文档里：每台电脑、每个机器人一份文档「pi 会话文档（主机名）」（改名前建的叫「pi 终端画面（主机名）」，标题不变），每个 session 一页，connect 时就建好，卡片一发出就带链接。点卡片的引用区直接打开本 session 那一页

1. 在企业微信「工作台 → 智能机器人 → 找到这个机器人 → 编辑 → 可使用权限」授权「文档」，点「查看使用方式」，复制 **streamableHTTP URL**（不是 JSON Config）
2. 在 pi 中运行 `/wecom-aibot config --scope global edit`，选「会话文档」，粘贴地址。地址必须是 `https://…qq.com/…`；它含 apikey，等同于密码，不要发到聊天里
3. 运行 `/wecom-aibot connect`，新发的控制卡就带页面链接

- **权限**：建文档时设为企业内的人需申请、企业外拒绝；默认推送目标是单聊时，那个人在建页时就加为只读成员，之后第一次点「刷新卡片」的人也会加入。群里其他人看得到链接，但要申请才能打开
- **图标**：建文档时把 pi 的彩色 logo（项目里的 `src/extension/assets/pi-logo.png`）传进这份文档，控制卡来源行的图标就用它。网关自己画的卡（问发给哪个会话、「已发送」、在线会话卡、停用的旧卡）也用它：网关从 pi 发来的控制卡里记下这个地址。没配文档、还没传上，或网关刚启动、还没有 pi 发过控制卡时，用 LobeHub 图标库的单色 PNG（`registry.npmmirror.com`）。logo 本来就是公开的，图片地址不登录也能打开
- **内容**：标题是目录和完整 session ID，一行写明模型 · 供应商 · 状态 · 更新时间；然后是「最近回复」（最近 3 轮，每轮写时间和提问的第一行）、「最近通知」（`wecom_send` 带 `content` 的最近 3 条，没有就不写），按正文显示，不套代码块，也不放终端画面。回复和通知按会话记录读，pi 重启后照样有；Secret 和文档地址会被遮盖；每段最多 8000 字。每次整页覆写，只写文字，不放图片：文档里的图片地址不用登录就能打开，删页也收不回
- **何时写**：connect 发卡、任务完成卡、通知卡发出时立即写；点「刷新卡片」时写；每轮任务结束时自动写，离上次写至少隔 30 秒。同一时间只写一次，期间的请求合并成下一次
- **记录与清理**：文档服务列不出、也删不掉文档，所以本机在插件目录的 `session-doc.json` 里记下文档和各 session 的页面（同一台电脑上的 pi 共用这份记录，读写加锁）。旧版本的记录叫 `screen-pages.json`，第一次用到时自动改名，以前建的页面照样能找到。新建页面时顺带删除 7 天没有刷新过的页面；`/wecom-aibot reset` 删除这台电脑登记的全部页面。文档本身需要时在企业微信里手动删除
- **出错时**：文档写入失败时卡片顶部标红「文档不可用」，三行画面照常更新，「窗口记录」写出原因。授权有效期为 7 天（工作台写明），过期后到「可使用权限」重新授权；地址变了就到 edit 里重填。没有配置地址时，「刷新卡片」只更新卡片上的三行，「窗口记录」写「未配置文档」

### 欢迎与在线会话卡

企业微信在用户**当天首次进入机器人单聊**时发送 `enter_chat` 事件。已有正式接入且允许该用户访问的 pi 时，机器人通过独立的 `aibot_respond_welcome_msg` 接口回复一张在线会话卡；不启动任务，也不依赖用户已经发过消息。只有临时识别连接、没有可访问的会话或用户不在白名单时不发欢迎卡

欢迎卡和 `/wecom-aibot sessions` 是同一张在线会话卡，正文就是会话列表，**不选目标**，也不突出哪一个会话：

```
[pi] 在线会话
7 个在线会话
第 1/2 页 · 09:47 的状态
下拉框选会话，点「打开会话」发出它的控制卡，列表留着接着用；…
执行中  pi-wecom-aibot · 1d86 · claude-opus-5-5   ← 每个会话一行：忙闲 | 文件夹 · ID 末 4 位 · 模型，按接入顺序
空闲    home · 0001 · cn:deepseek-v4.1-flash
空闲    api-server · gpt-6-astra
执行中  home · 0003 · deepseek-v4-pro
空闲    docs · glm-5.3
会话 1/2  [ pi-wecom-… · 1d86 · 执行中 ▾ ] ← 和这一页的行一样，从第一行开始
[打开会话] [刷新列表]
[上一页]   [下一页]                         ← 只有一页时没有这一行
```

- **一页放 5 个**：企业微信的卡片正文最多 6 行（二级标题＋文本列表，文档 101032），第 6 行留给点按钮的结果（如「选的会话已离线」）。其他地方放不下列表：引用区只显示 3 行，二级文本建议不超过 112 字，下拉框最多 10 项。下拉框和这一页的行一一对应
- **翻页**：超过 5 个会话时，按钮多一行「上一页」「下一页」，到头接上另一端；每次翻页重新问一遍各个 pi 的忙闲。群里只翻点击人那一份。一行两个按钮（一行 3 个会被截断）
- **打开会话**：下拉框选的会话发一张新的控制卡到这个聊天，没动下拉框就是这一页的第一行。列表不变，「动态」写「已打开「文件夹 · ID 末 4 位」的控制卡」，下拉框停在刚打开的会话，接着选下一个会话再点就行，一张列表能打开多个会话。发提示词、切换模型、中止任务都在打开的控制卡上做。群聊里新控制卡全群都看得到，列表的记录只改点击人那一份
- **刷新列表**：重新问一遍各个 pi 的忙闲，就地重画这一页，下拉框留在原来选的会话
- **旧列表卡**：旧版列表上的「查看会话」「发提示词」「切换模型」「中止任务」点了，都按「打开会话」处理
- **会话 ID**：列表上不写；打开的控制卡上有，也可以发 `/wecom-aibot --session-id <id>` 查
- 选的会话已离线时，列表按现在在线的会话重画，写明「选的会话已离线，请选另一个」
- 旧版本的分页会话卡（「下一页」「回首页」、每个会话一个按钮）和卡片上的「设为目标」「清除目标」点了，卡片变成「这张卡已停用」

### 同时开着多个 pi

多个会话在线时，规则和一个会话时一样：每条消息看命令、看引用，都没有就问，见[发送任务](#发送任务)。网关不按在线人数猜，也不记上一条发给了谁

- 接着某个会话说：在它的结果卡上点「发提示词」；或者直接发，在问的卡上选那个会话再确认；也可以用 `--session-id <id> send`
- 群聊里每个人的消息各问各的，只有发消息的人能选
- 引用只定向当前消息；引用的会话已离线时，改为问发给谁，不会自动发给别的会话
- 显式指定的 session 离线或写错时，机器人会回一条错误并附上当前会话列表

### 共享网关

共享网关不需要单独启动或停止：

- 第一个 pi 正式接入（`/wecom-aibot connect`）或临时识别（离线 `config whoami`）时，网关自动启动。临时连接不是可接收任务的在线会话
- 其他 pi 复用同一个网关，不会各自再连一条企业微信长连接
- 最后一个 pi 执行 `/wecom-aibot disconnect`、退出或崩溃后约 1.5 秒，网关自动退出；缓存里的卡片、等待选择的消息和 session 内的送达记录都不会阻止退出
- `/wecom-aibot connect` / `/wecom-aibot disconnect` 只控制**当前 session** 是否接入，不停止 pi 进程、不修改配置，也不影响其他已接入的 pi。要停止全部，就在每个 pi 窗口各执行一次 `/wecom-aibot disconnect`
- 断开后企业微信侧不会收到「已断开」提示。网关退出前的约 1.5 秒内，若有消息到达，会回复「当前没有在线的 pi 会话」；之后长连接关闭，机器人不再响应，需要重新 `connect`

### 完成后通知

- **企业微信发起的任务**：结果以一张结果卡发回原聊天，不回复原消息；pi 拿到的是来源行、用户正文和图片/文件说明，不带 chatid
- **电脑上布置的任务**：先在当前 session 执行 `/wecom-aibot connect`，再在任务里加一句「完成后发企业微信通知我」，pi 做完后推送到默认推送目标；要发到别的群，告诉 pi 那个群的 chatid
- `wecom_send` 省略目标时：企业微信任务优先发回**来源聊天**，本地任务才使用当前接入采用的默认推送目标（`defaultChatId` / `defaultChatType`）
- **断线恢复**：任务结果和已安排的完成通知在当前 pi 内保留快照，确定尚未发送时恢复连接后补发；若已尝试发送但确认丢失，则提示结果未知，不自动重复推送。明确被服务端拒绝的通知也不会自动重试。停止或退出当前 pi 会清除这些内存中的待发通知

> [!NOTE]
> 企业微信要求对方先给机器人发过消息，机器人才能主动推送给他（或那个群）。通知是一张控制卡，正文在点引用区打开的文档页里，见下方「通知卡片」。暂不支持发送图片或文件

## 🃏 通知卡片

pi 主动推送的卡片都是控制卡（企业微信的 `button_interaction` 模板卡片），见[每个 session 的控制卡](#每个-session-的控制卡)：任务完成、`wecom_send` 通知都发一张新的控制卡，旧卡不会被改动。卡片上不放正文，「窗口记录」写标题，正文在文档页里

| 场景 | 发什么 | 按钮 |
| :--- | :----- | :--- |
| 每次 connect / 首次接受新聊天的任务 | session 自己的控制卡，下拉框列出当时在线的所有会话；connect 每次发新的，新聊天已有送达记录时复用 | 会话下拉框；刷新卡片、发提示词、切换模型、中止任务 |
| 企微侧 `card` | 显式补发一张控制卡副本 | 同上 |
| `/wecom-aibot test` | 一张控制卡，「窗口记录」写「🧪 部署测试」 | 同上 |
| 进入单聊 / 企微侧 `sessions` | 在线会话卡：正文每个会话一行，一页 5 个 | 会话下拉框；打开会话、刷新列表，多页时加上一页、下一页（打开会话发一张新的控制卡，列表留着） |
| 没有引用、也没写 `--session-id` 的普通消息 | 「这条消息发给哪个会话？」，4 分钟内有效 | 会话下拉框（最多 10 个）；确认发送、取消发送 |
| 企微发来的任务、本地运行（`all-runs`）、「发提示词」的任务 | 一张新的控制卡，和控制卡同样的布局和按钮，只是初始状态不同：来源行写「已完成」（绿）或「已中止」「未执行」（红），「窗口记录」写「✅ 完成：任务首行」这类结果，引用区是任务结束时窗口的最后三行，下拉框默认是发出它的会话。点任意按钮后变回实时状态。被拒收时改发带回复全文的 Markdown。企微任务不回复原消息，运行期间也不发状态消息：长连接的回复 stream 附带卡片会被接受但不显示，所以结果单独发卡；没有执行的（忙、已停止、清空排队）仍回复原消息说明 | 同上 |
| `wecom_send` | 一张控制卡，「窗口记录」写 `📣 标题`（`content` 的第一行）；`after_settle` 的写结束状态，立即发的写实时状态 | 同上 |
| 执行中、排队、帮助、错误及错误附带的会话列表 | 文字 | — |

- **点按钮**：网关先检查点击人的白名单。问的卡由网关处理；在线会话卡的「打开会话」请下拉框选的会话发一张新的控制卡，翻页和刷新由网关处理；控制卡的按钮交给卡上显示的那个会话（下拉框选了别的，就交给选的那个，只切换不执行），pi 约 4 秒内答复（「刷新卡片」要写文档页）。「窗口记录」一行记下操作结果，按钮不往聊天里另发消息。企业微信只允许在点击后 5 秒内更新卡片，所以卡片不会自己刷新。控制卡的按钮见[每个 session 的控制卡](#每个-session-的控制卡)
- 旧版本发的结果卡、通知卡上的「截图」「全文」等按钮已停用：点了卡片就地变成「这张卡已停用」，不发新消息。看回复点新控制卡的引用区
- 会话已离线、pi 没有及时响应，卡片上会写明。网关重启后，控制卡可由所属 pi 重建并原地更新；旧内容通知卡没有缓存时，点击结果改为短消息
- 群聊里卡片对全群一起更新（控制卡的中止确认除外，只更新点击人那一份），记录的是发生了什么，不公开点击人的 userid，也不把个人选择写成全群的当前目标
- 企业微信拒收任务结果或通知的卡片时（如字段超限），同样的内容改发一条 Markdown；connect 发的控制卡被拒绝则记录并提示，不把没有按钮的 Markdown 当作控制卡已送达。拒收在线会话卡时，命令返回文字列表，欢迎语则在 5 秒窗口内改为文字欢迎语；拒收问的卡时，这条消息不发出，回复里说明怎样用引用或命令指定会话。点击更新被明确拒绝时，操作确认改发短消息。发送结果未知时都不自动发第二份

## 🧰 命令速查

| 命令                      | 作用                                                       |
| :------------------------ | :--------------------------------------------------------- |
| `/wecom-aibot`            | 弹出子命令菜单，标题显示当前接入状态                       |
| `/wecom-aibot status`     | 查看连接状态、默认推送目标、通知设置和配置文件位置         |
| `/wecom-aibot config`     | 查看或修改配置：`[--scope <global\|session>] <show\|edit\|set\|unset\|whoami>`；whoami 发验证码识别聊天；不带动作时列出全部写法供选择；只保存，不接入也不断开 |
| `/wecom-aibot test`       | 发送一张部署测试用的控制卡，可点按钮验证回调               |
| `/wecom-aibot connect`    | 配置齐全后正式接入，在默认聊天发一张本 session 的新控制卡；接入配置改变后确认切换 |
| `/wecom-aibot disconnect` | 仅注销当前 session；不修改配置，最后一个 pi 注销后网关退出 |
| `/wecom-aibot log`        | 查看最近 20 条运行记录                                     |
| `/wecom-aibot reset`      | 删除全局配置和本机登记的文档页，并停止当前 pi 的接收（需交互确认） |
| `/wecom-aibot --help`     | 查看全部命令；配置字段说明见 `/wecom-aibot config --help`  |

`/wecom-aibot disconnect` 只取消当前 session 的排队消息和待发通知，已开始的任务在电脑上照常跑完，但结果不再发回企业微信；其他已接入的 pi 不受影响。它不会改写配置文件；之后需要在当前或新 session 中手动 `/wecom-aibot connect` 才会接入，最后一个 pi 断开后共享网关自动退出

`config whoami` 等待或确认期间，如果机器人凭据被更换或配置被删除，旧识别结果不会写入配置，请重新识别。`reset` 若报告删除失败，当前 pi 已停止，但凭据可能仍在磁盘；请检查提示的文件权限后重试

`reset` 删除全局配置文件：BotID、Secret、默认推送目标、通知设置、白名单和会话文档地址一起删除，各 session 的覆盖文件保留；删除前先删掉这台电脑登记的文档页（文档本身无法用接口删除）；之后需要重新 `/wecom-aibot config --scope global edit`。没有交互界面时 `reset` 不删除任何文件。它只停止当前 pi 的接入；其他已连接的 pi 仍会继续收发，直到它们各自 `disconnect` 或退出

## 🔄 升级与卸载

### 升级

| 安装方式 | 命令                                                                     |
| :------- | :----------------------------------------------------------------------- |
| Git 仓库 | `pi update git:github.com/cobia68/pi-wecom-aibot`                            |
| 本地目录 | 在插件目录执行 `git pull`，再执行 `npm ci --omit=dev --legacy-peer-deps` |

`pi update <source>` 只更新这一个插件，等价于 `pi update --extension <source>`；`pi update --extensions` 更新所有已安装的插件；不带目标的 `pi update` 只更新 pi 本身。用 `@标签` 固定过版本的，`pi update` 不会移动它，换版本要用新标签再执行一次 `pi install`

旧版本的字段 `sendMode`、`notifyEveryRun`、`enabled`、`welcome`、`notificationMode`、`screenshotTheme` 等不再读取，也不转换成新字段；下次保存同一层配置时从文件中删除。通知现在一律是卡片。截图功能已移除：企微侧的 `screen` 命令、`wecom_send` 的 `screenshot` 参数和引用截图定位会话都没有了，看画面点控制卡的「刷新卡片」；`wecom_send` 的 `tail_paragraphs` 参数已移除。原来「每轮结束都通知」的，升级后重新设置：

```text
/wecom-aibot config --scope global set notificationScope=all-runs
```

命令写法也变过：作用域改为写在动作前的选项（`config global set …`、`config set --scope global …` 都写成 `config --scope global set …`），`whoami` 移到 `config` 下（`/wecom-aibot config whoami`），只有 `--help` 能打开帮助。企微侧的目标必须放在动作前，例如 `cancel --sessionid <id>` 改为 `--sessionid <id> cancel`；旧写法不再执行，报错里会给出新写法。企微发来的任务，结果从回复原消息的 Markdown 改为一张结果卡，所以不能再引用结果接着说，改在结果卡上点「发提示词」。pi 与网关之间的协议版本升为 13：新旧版本不能共用一个网关。「画面文档」改名为「会话文档」（配置字段仍是 `docMcpUrl`）：已建的文档保留原标题；本机记录从 `screen-pages.json` 改名为 `session-doc.json`，第一次用到时自动改，以前的页面照样能找到。控制卡改为「刷新卡片」「发提示词」「中止任务」，回复和通知正文写进文档页、点引用区看，加「会话」下拉框，发提示词改为两步，不再有「设为目标」「刷新状态」「截图」；任务结果、`wecom_send` 通知和部署测试也都发控制卡，不再有「全文」「截图」「测试点击」。旧控制卡被点击时就地换成新版式。网关不再记「当前目标」：没有引用、也没写目标的消息，机器人逐条问发给哪个会话；旧卡上的「设为目标」「清除目标」点了，卡片变成「这张卡已停用」。企微命令的目标选项改写成 `--session-id`，和 pi 命令行一样；`--sessionid` 照样能用

更新只替换磁盘上的文件，正在运行的 pi 和共享网关进程仍然持有旧代码，`/reload` 也换不掉已经在跑的网关。请关闭所有使用这个机器人的 pi 窗口（共享网关会在最后一个窗口退出后约 1.5 秒自行结束），再重新打开，并逐个执行 `/wecom-aibot connect`

### 卸载

1. 在 pi 中执行 `/wecom-aibot reset`，删除全局配置里的 BotID 和 Secret；在 session 覆盖里保存过凭据的，再删除 `~/.pi/agent/wecom-aibot/sessions/`
2. 移除插件：
   - Git 仓库：`pi remove git:github.com/cobia68/pi-wecom-aibot`，会一并删除克隆的仓库
   - 本地目录：在插件目录执行 `pi remove .`，只取消登记，不删除目录
3. 可选清理：各项目里的 `.pi-wecom-aibot-files/`，以及插件文件夹里的网关状态 `~/.pi/agent/wecom-aibot/gateway/` 和文档页记录 `session-doc.json`（旧版本叫 `screen-pages.json`）；在工作台撤销机器人的「文档」授权，按需在企业微信里删除「pi 会话文档」（或改名前的「pi 终端画面」）文档

## ❓ 常见问题

<details>
<summary><b>给机器人发消息没有反应</b></summary>

- 确认至少有一个 pi 正在运行并已接入：执行 `/wecom-aibot status`，第一行应为「🔌 企业微信智能机器人：已接入」。⏳ 表示正在连接或重连，🛑 表示已停止（按提示运行 `/wecom-aibot connect`），💤 表示当前 session 未接入。四个图标宽度一致，状态变化时标题不会左右跳
- 群聊中需要先 @机器人；没有引用的消息机器人会问发给哪个会话，只有发消息的人能选
- 目标 pi 重新接入或网关重启后要重选，不会自动恢复上一次选择
- 设置了白名单时，名单外的人发的消息会被直接忽略
- 执行 `/wecom-aibot log` 查看运行记录。出现 `gateway process exited` 或 `gateway launch failed` 时，多半是本地目录安装漏了 `npm ci`，或 PATH 中找不到 Node.js

</details>

<details>
<summary><b>提示「机器人连接已被其他机器或旧客户端接管」</b></summary>

同一个机器人同一时间只能在一处连接。另一台电脑或另一个系统用户启用了同一个机器人时，这里会被挤下线。确认只在一处使用后，在任一 pi 中执行 `/wecom-aibot connect` 恢复

</details>

<details>
<summary><b>连接失败，提示核对 BotID/Secret</b></summary>

- 执行 `/wecom-aibot config --scope global edit` 重新填写（凭据由 session 覆盖时用 `config --scope session edit`）
- 在企业微信管理后台确认机器人仍是「API 模式」+「长连接」
- 连续被拒绝几次后插件停止重试；改好后执行 `/wecom-aibot connect` 重新连接

</details>

<details>
<summary><b>更换 BotID 或 Secret 后连不上</b></summary>

保存配置不会切换已有的接入：已接入的 pi 窗口（包括当前窗口）在重新 `connect` 前仍使用接入时的凭据。在这些窗口执行 `/wecom-aibot connect` 确认切换，或者关闭所有 pi 窗口后重新打开，再逐个执行 `/wecom-aibot connect`

</details>

<details>
<summary><b>收不到主动推送</b></summary>

- 对方需要先在企业微信里给机器人发过消息
- 企业微信限制每个聊天每分钟最多 30 条、每小时最多 1000 条消息；卡片点击后的更新也计在内
- 没有默认推送目标时，用 `/wecom-aibot config --scope global whoami` 设置，或在任务里写明发给谁
- 失败原因可以在 `/wecom-aibot log` 中查看

网络短暂中断时，已完成的结果会在恢复连接后补发；退出 pi 会取消还没发出的通知

</details>

<details>
<summary><b>怎么查自己的 userid 或群的 chatid</b></summary>

执行 `/wecom-aibot config whoami`，pi 显示一个 6 位验证码；在要查的聊天里把它发给机器人（群聊需 @机器人），pi 显示 chatid 和 userid。这样只查看，不保存；写成 `config --scope global whoami` 或 `config --scope session whoami` 时，确认后设为那一层的默认推送目标。离线时会临时连接识别，无需先 `connect`。默认等 5 分钟，可用 `--wait <秒>` 调整，10～600 秒。等待期间其他消息照常处理。已连接时确认更换目标只保存配置，不断开当前接入；运行 `/wecom-aibot connect` 后改用新目标

</details>

<details>
<summary><b>日志里经常出现 WebSocket closed，能否只在发送时连接</b></summary>

网关会自动重连：30 秒内恢复只记日志，超过 30 秒提醒一次，恢复后再提醒。日志里的 `1006` 只表示异常断开，不能据此判断是企业微信服务端还是中间网络造成的

插件需要长连接实时接收任务、引用回复和卡片点击，断开期间收不到，所以保持连接。要暂停请用 `/wecom-aibot disconnect`

</details>

<details>
<summary><b>机器人回复「当前等待任务较多，请稍后重试」</b></summary>

每个 pi 最多排队 50 条消息，等前面的任务处理完再发

</details>

## 🛠️ 开发

生产代码按运行归属组织：

- `src/extension/`：pi 侧入口、命令、会话桥接（`bridge-session.ts`）、状态栏（`footer-status.ts`）、`config whoami` 识别聊天（`whoami.ts`）、`wecom_send` 工具（`wecom-send.ts`）、配置值的显示写法（`config-display.ts`）、读会话数据（`session-data.ts`）和入站媒体。企微来的轮次：`turn-guidance.ts` 写附加的系统提示，`next-steps.ts` 从回复里读出下一步。控制卡：`control-view.ts` 画卡片，`model-options.ts` 排列和分页「切换模型」的模型，`control-receipts.ts` 记录每个聊天收到的控制卡（送达记录与复用）。文档：`doc-mcp.ts` 是文档 MCP 客户端，`session-doc.ts` 管理会话文档与各 session 的页面，`session-page.ts` 管本 session 那一页何时建、何时写。`terminal/` 读终端画面的文字（卡片上的三行），并遮盖其中的已知密钥
- `src/gateway/`：独立网关进程（`runtime.ts` 路由消息和点击）、企业微信长连接和企微侧命令（`command.ts`）。网关自己画的卡：`ask-card.ts` 是问发给哪个会话的卡，`session-picker.ts` 是在线会话卡，`session-view.ts` 是它们共用的会话写法（含给聊天的文字列表），也给控制卡补全会话下拉框；`session-poller.ts` 问各 pi 忙不忙。控制卡的内容都由 pi 画
- `src/shared/`：双方共用的协议、通知契约和格式规则，不依赖任何一端实现；`card.ts` 是卡片模型和渲染，`control-card.ts` 是控制卡的 ID、按钮键、下拉框键和会话的写法

扩展入口由 `package.json` 的 `pi.extensions` 声明为 `src/extension/index.ts`；如果原先直接指定根目录 `index.ts` 加载，请更新路径。按包安装的用户无需修改设置

开发时需要安装完整依赖，不要使用 `--omit=dev`；Windows 和 Linux 各用独立的克隆及 `node_modules`：

```bash
npm ci
npm run check
```

`check` 包含类型检查、递归发现的全部测试和真实 pi loader 的扩展加载检查。也可以单独运行：

```bash
npm test -- --test-name-pattern=notification
node --import tsx --test tests/shared/notification.test.ts
npm pack --dry-run --json
```

源码直接发布，不需要生成 `dist/`。新增生产文件放入 `src/`，测试放入 `tests/`，无需逐项修改发布白名单或测试命令。修改后在 pi 中执行 `/reload` 加载新入口
